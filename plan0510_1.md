# CaoshuReader OOM 问题优化方案

## 一、问题诊断

| 场景 | 当前状况 | OOM 根因 |
|------|---------|---------|
| **单字训练 (`train.py`)** | 图像已固定 resize 到 `448×448` | batch_size/grad_accum 太大，或中间激活值占显存 |
| **验证集测试 (`test_caoshu.py`)** | 同上 | batch_size=32 对老显卡可能过大 |
| **整图 Pipeline (`pipeline.py`)** | YOLO **直接读取原图**检测 | 用户上传超高分辨率扫描件（如 `4000×6000`）时，YOLO 前向传播会 OOM |

**注意**：你给出的代码片段里 `model.generate(...)` 是 **CalliReader（VLM）的文本生成接口**，但 CaoshuReader 的推理流程是 `ViT → MLP1 → Resampler → 相似度匹配`，**不走 generate()**。所以那段代码不能直接套用到 CaoshuReader。

---

## 二、优化方案

### 方案 A：训练/测试阶段（单字 448×448）

核心思路：**用 `torch.cuda.amp.autocast()` 包裹前向传播 + 定期 `empty_cache()`**

#### 1. `train.py` 修改

```python
# === 在 main() 开头初始化 scaler ===
amp_enabled = (device.type == 'cuda')
scaler = torch.cuda.amp.GradScaler() if amp_enabled else None

# === 训练循环内 ===
while step < args.total_steps:
    for imgs, labels in loader:
        imgs = imgs.to(device)  # 先不转 bfloat16，交给 autocast 管理

        with torch.cuda.amp.autocast(enabled=amp_enabled):
            imgs_bf16 = imgs.to(torch.bfloat16)
            vit_feats = get_visual_embed(imgs_bf16, vit, mlp1)
            pred = resampler(vit_feats)

            chars = [dataset.idx2char[l.item()] for l in labels]
            token_ids = tokenizer(
                chars, return_tensors='pt', add_special_tokens=False,
                padding=True, truncation=True, max_length=4,
            ).input_ids[:, 0].to(device)
            with torch.no_grad():
                tgt_embed = tok_embeddings(token_ids)

            loss = alignment_loss(pred, tgt_embed)

        loss_item = loss.item()
        if scaler is not None:
            scaler.scale(loss / args.grad_accum).backward()
        else:
            (loss / args.grad_accum).backward()

        if (step + 1) % args.grad_accum == 0:
            if scaler is not None:
                scaler.unscale_(optimizer)
            nn.utils.clip_grad_norm_(resampler.parameters(), 1.0)
            if scaler is not None:
                scaler.step(optimizer)
                scaler.update()
            else:
                optimizer.step()
            scheduler.step()
            optimizer.zero_grad()

            # 定期清理显存碎片（每10个有效step一次）
            if (step + 1) % (args.grad_accum * 10) == 0:
                torch.cuda.empty_cache()
```

**效果**：autocast 会自动把支持的 op 降到 bfloat16，减少中间激活值显存占用约 30%~50%。

同时建议在开头加显存预估提示：

```python
if device.type == 'cuda':
    torch.cuda.empty_cache()
    free_mem = torch.cuda.get_device_properties(0).total_memory - torch.cuda.memory_allocated()
    est_mem_per_sample = 25 * 1024 * 1024  # 约 25MB/样本（bfloat16）
    est_total = est_mem_per_sample * batch_size
    print(f"GPU memory: {free_mem/1024**3:.1f}GB free, estimated {est_total/1024**3:.2f}GB needed")
    if est_total > free_mem * 0.9:

        print(f"⚠️  WARNING: batch_size={batch_size} may cause OOM, consider reducing to {suggested}")
```

### 方案 B：整图 Pipeline 推理阶段（YOLO 检测原图）

这是**你建议的核心逻辑真正该放的地方**。如果用户上传一张 `6000×4000` 的扫描卷轴，YOLO 会在 `self.model(img)` 这一步直接 OOM。

#### 1. `visualizer.py` 修改

新增 `detect_and_visualize_array()` 方法，并让 `detect_and_visualize()` 支持分辨率限制：

```python
def detect_and_visualize(self, 
                       image_path: Union[str, Path], 
                       output_path: Union[str, Path] = None,
                       box_color: Tuple[int, int, int] = (0, 0, 255),
                       thickness: int = 3,
                       max_pixels: int = None) -> Tuple[np.ndarray, List[Dict]]:
    """
    检测并在原图上画框
    Args:
        max_pixels: 若指定，超过此像素数则自动等比缩放（防止OOM）
    """
    image_path = Path(image_path)
    img = cv2.imread(str(image_path))
    if img is None:
        raise ValueError(f"无法读取图像: {image_path}")
    
    # 分辨率限制（防止超高分辨率图像导致OOM）
    if max_pixels:
        h, w = img.shape[:2]
        if h * w > max_pixels:
            scale = (max_pixels / (h * w)) ** 0.5
            img = cv2.resize(img, (int(w*scale), int(h*scale)), interpolation=cv2.INTER_AREA)
            print(f"[Visualizer] 分辨率限制: {w}×{h} → {int(w*scale)}×{int(h*scale)}")
    
    return self.detect_and_visualize_array(img, output_path, box_color, thickness)

def detect_and_visualize_array(self,
                               img: np.ndarray,
                               output_path: Union[str, Path] = None,
                               box_color: Tuple[int, int, int] = (0, 0, 255),
                               thickness: int = 3) -> Tuple[np.ndarray, List[Dict]]:
    """直接传入 numpy 数组检测（供 Pipeline 调用，避免重复读取）"""
    results = self.model(img, conf=self.conf_thres, verbose=False)
    vis_img = img.copy()
    boxes_data = []
    for idx, box in enumerate(results[0].boxes):
        x1, y1, x2, y2 = box.xyxy[0].cpu().numpy().astype(int)
        conf = float(box.conf[0])
        cv2.rectangle(vis_img, (x1, y1), (x2, y2), box_color, thickness)
        boxes_data.append({
            "id": idx + 1,
            "bbox": [int(x1), int(y1), int(x2), int(y2)],
            "confidence": round(conf, 3),
            "center": [int((x1+x2)/2), int((y1+y2)/2)]
        })
    # ... 保存逻辑不变
    return vis_img, boxes_data
```

#### 2. `pipeline.py` 修改

在 `process_image()` 中加入分辨率限制，并复用已读取的图像：

```python
def process_image(self,
                 image_path: str,
                 output_dir: str,
                 topk: int = 3,
                 save_crops: bool = True,
                 debug: bool = False,
                 max_pixels: int = 1344 * 1344) -> Dict:
    """
    Args:
        max_pixels: 整图最大像素数，超过则等比缩放（防止YOLO OOM）
    """
    image_path = Path(image_path)
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)
    print(f"[Pipeline] 处理图片: {image_path.name}")
    
    # 0. 读取并限制分辨率
    orig_img_bgr = cv2.imread(str(image_path))
    if orig_img_bgr is None:
        raise ValueError(f"无法读取图像: {image_path}")
    h, w = orig_img_bgr.shape[:2]
    if h * w > max_pixels:
        scale = (max_pixels / (h * w)) ** 0.5
        new_w, new_h = int(w * scale), int(h * scale)
        orig_img_bgr = cv2.resize(orig_img_bgr, (new_w, new_h), interpolation=cv2.INTER_AREA)
        print(f"  [0/4] 分辨率限制: {w}×{h} → {new_w}×{new_h}")
    else:
        print(f"  [0/4] 分辨率: {w}×{h} (无需缩放)")

    # 1. YOLO 分割（直接传数组，避免重复读取）
    print("  [1/4] YOLO分割...")
    result_img_path = output_dir / f"{image_path.stem}_result.jpg"
    vis_img, boxes_data = self.visualizer.detect_and_visualize_array(
        orig_img_bgr, result_img_path
    )
    # ... 后续不变
    
    # 3. 裁剪单字时直接用 orig_img_bgr，不要再 cv2.imread()
    orig_img_rgb = cv2.cvtColor(orig_img_bgr, cv2.COLOR_BGR2RGB)
    # ... 后续不变
```

## 三、参数建议

| GPU 显存 | train.py batch_size | test_caoshu.py batch_size | pipeline max_pixels |
|---------|---------------------|---------------------------|---------------------|
| 24 GB | 16 | 32 | 1344² (~1.8M) |
| 16 GB | 8 | 16 | 1344² |
| 12 GB | 4 | 8 | 1024² (~1M) |
| 8 GB | 4 (grad_accum=32) | 4 | 1024² |

**关于 `max_pixels` 的取值**：
- `1344 * 1344 = 1,806,336`：适合大多数书法作品，YOLO  comfortably handle
- `1024 * 1024 = 1,048,576`：更保守，适合低显存环境
- `1920 * 1920 = 3,686,400`：如果你需要保留极高精度

**为什么不用切片推理？**
CaoshuReader 的 Pipeline 已经是 "YOLO 检测 → 裁出单字 → 单字识别"。单字识别输入固定 `224×224`，不存在切片需求。需要切的是**整图在 YOLO 阶段的分辨率**，所以用等比缩放即可。
